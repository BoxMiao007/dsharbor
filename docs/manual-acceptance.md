# Windows 手动验收手册（发布前完整流程）

每次发布前在 Windows 真机上按本手册复核。每步给出「操作」与「期望结果」；不满足时看文末「排查」。

> 开发机参考：自动化脚本与截图存放于 `C:\Users\<你>\AppData\Local\Temp\dsharbor-test`（`launch-app.ps1`、`capture-window2.ps1`、`kill-app.ps1` 等）。正式验收只需按本手册手动操作。

## 0. 构建与产物（WSL2 侧）

- 操作：`pnpm exec tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc`
- 期望：退出码 0；产物 `target/x86_64-pc-windows-msvc/release/bundle/nsis/DSHarbor_<版本>_x64-setup.exe`（2 MiB 量级；打包会连带前端构建与桥接插件 tgz）。

## 1. 安装

- 操作：双击安装包，按中文向导完成（静默安装等价命令：`DSHarbor_<版本>_x64-setup.exe /S`）。
- 期望：装到 `%LOCALAPPDATA%\DSHarbor`（当前用户，无需管理员）；注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\DSHarbor` 中 名称 DSHarbor、版本正确、发布者 BoxMiao007。

## 2. 启动与首次配置

- 操作：从开始菜单打开 DSHarbor（或运行 `%LOCALAPPDATA%\DSHarbor\dsharbor.exe`）；在末尾「关于」卡片依次点「打开 GitHub 仓库 / 打开 DSH 官网 / 打开配置目录 / 打开日志目录」。
- 期望：主窗口出现；「启动方式」默认「官方 npx 命令」（说明里显示实际执行的命令 `npx --yes @deepseek-ai/dsh web --no-open`）；端口提示显示当前生效值（如「3080（来自 DSH 配置的 webserver 块，host …）」）；「托盘单击打开」与 WSL 发行版用自绘下拉框（弹层是 12px 圆角暗色面板、已选中那一项行首带 ✓；**静止（指针不在列表里）时蓝底落在当前值那一行，指针一进列表或键盘一按上下键，蓝底就只跟光标走、当前值那一行让出底色（不固定在已选中行上）**，Esc / 上下方向键 / 回车可用）；「桥接插件」卡片显示目标环境（Windows）与安装状态；「最近输出 / 操作输出」为折叠块——点击标题行展开、再点收起（空态显示「（暂无输出）/（暂无操作）」）；只显示最近 15 行（高 310px），超出在框内滚动，**文本可拖选复制，拖选期间日志刷新不会把选区清掉（松手后选区仍在，可以复制）**，标题行右侧「复制」按钮一键拷走全量（点后短暂变「已复制」）；会话卡片里「托盘单击打开」与同卡片的状态行、按钮、日志框左右对齐（无额外缩进）；**状态行从左到右依次是登录徽章、状态徽章、版本徽章、PID、端口**；登录徽章里的感叹号图标悬停或聚焦时显示气泡说明「登录链接就绪后即可打开 DSH 界面」，正常态不再占一行文字（登录失败时才在按钮行**下方**显示原因原文，不影响按钮位置）；**「启动 DSH / 停止」（同一个按钮：停止态是「启动 DSH」、运行中变「停止」）与「重启 DSH」为一组，「当前程序打开 / 浏览器打开」为另一组，两组在同一行横向并排，第二组（打开界面）贴卡片右缘、与左侧控制组分列左右（组内间距 10px；窄窗口下整体换行）**；**会话卡片状态徽章右侧有版本徽章**（没成功启动过 DSH 时显示「DSH 版本未知」，两个四角星图标 + `DSH v…`，外观与「已停止」同款）；**「启动方式」「桥接插件」卡片标题可点击收起/展开（默认展开、标题带 ▸、悬停或聚焦时是圆角高亮背景，界面各处不留直角），「DSH 会话」与「关于」不可收起；**收起后标题行显示摘要徽章（「启动方式」显示当前方式名、「桥接插件」显示已安装 / 未安装），展开时隐藏**；「关于」卡片显示壳与核心库版本、DSH 版本、MIT、仓库、官网、配置目录与日志目录，四个按钮分别打开 GitHub 仓库、DSH 官网、`%APPDATA%\DSHarbor`、`%USERPROFILE%\.dsh\logs`（后两个用资源管理器打开对应目录）**——这四个按钮已分别放进「项目仓库 / DSH 官网 / 配置目录 / 日志目录」条目内部（贴在条目右侧，与上面无按钮的条目同一列对齐）**；**全页所有徽章 + 「最近输出 / 操作输出」的「复制」胶囊统一大小：高度 28px、水平内边距 10px、字号 13px（登录 / 状态 / 版本 / 端口提示 / 收起后的卡片摘要都在内，不随图标或文字长短变化）**；**壳重启前曾成功启动过 DSH 的，本次打开界面后版本徽章直接显示上次记下的版本号，不是「DSH 版本未知」（见第 6 步）**。

## 3. 启动 DSH 并取登录链接

- 操作：点「启动 DSH」（首次会自动下载 npx 包，稍慢）。
- 期望：状态徽章先显示「启动中」（蓝色、带转圈），拿到登录链接后变「运行中」并出现 PID 与端口；**版本徽章在几秒内从「DSH 版本未知」变为实际版本（如 `DSH v0.2.0-rc.2`，四个启动方式都要能读到；WSL 模式下不应把发行版欢迎语误当版本号）**；**点「启动 DSH」（或「停止」/「重启 DSH」）后同一卡片的「最近输出」自动展开**（启动后同一个按钮的文案变成「停止」，点它就是停止；停止后回到「启动 DSH」）；登录徽章（状态行第一个）在拿到链接后变「桥接就绪」（未安装桥接插件时显示「日志兜底就绪」，同样可用）；**不会弹出系统浏览器**（壳自动追加 `--no-open`；界面用「当前程序打开」在壳窗口查看，或点「浏览器打开」显式交给系统浏览器）。失败时显示含退出代码与最近输出的提示，并给出诊断日志路径线索（`~/.dsh/logs/startup-*.log`）。

## 4. 两种打开方式与窗口独立性

- 操作：点「当前程序打开」；再点「浏览器打开」；然后先关 DSH 窗口（观察主窗口是否还在），再关主窗口（观察 DSH 窗口是否还在）。
- 期望：「当前程序打开」弹出的 DSH 窗口**已是登录态**（不需要手工拼接 token 链接），标题为 DeepSeek Harness；DSH 窗口尺寸随主显示器自适应（高度不越出屏幕下边界）；「浏览器打开」在系统默认浏览器打开同一界面；**两个窗口相互独立**——关 DSH 窗口后主窗口仍在；关主窗口后 DSH 窗口仍在（DSH 后端与托盘常驻），托盘「打开启动界面」可随时找回主窗口。

## 5. 轻量模式循环（3~5 轮）

- 操作：右键托盘确认菜单六档齐全（**浏览器打开 / 当前程序打开 / 打开启动界面 / 重启 DSH / 停止 DSH / 完全退出**）→ 关闭主窗口 → 任务管理器观察内存 → 单击托盘图标（默认打开启动界面；Win11 图标可能收在「隐藏的图标」小箭头里）。
- 期望：关窗后壳进程与 DSH 后端仍存活，界面内存明显下降（参考量级：两窗全开约 1037 MB → 关窗约 474 MB）；单击托盘后窗口原地重建，仍为「运行中」且登录链接就绪；重复多轮无白屏。在界面把「托盘单击打开」改为「当前程序打开的窗口」后，单击托盘应直接打开 DSH 窗口（未就绪时回退启动界面）。

## 6. 重启与完全退出

- 操作：界面「重启 DSH」（运行中一键重启）；再托盘「重启 DSH」；再托盘「停止 DSH」；然后界面点「重启 DSH」重新拉起，最后托盘「完全退出」。
- 期望：重启后 DSH 的 PID 更换、登录链接重新就绪、窗口内容可用；**托盘「完全退出」后重新打开 DSHarbor，会话卡片版本徽章仍显示上次记录的版本号（不是「DSH 版本未知」；值存在 `%APPDATA%\DSHarbor\dsh-version.txt`），点「启动 DSH」后按原规则重新查询并刷新**；「停止 DSH」后状态回「已停止」、PID/端口清空、`netstat` 无 3080 LISTENING，但**壳与窗口仍在**；完全退出后壳与 DSH 进程全部消失，`netstat -ano | findstr "3080"` 无 LISTENING 残留。

## 7. 意外退出恢复

- 操作：启动 DSH 后，在任务管理器结束其 node 进程（或 `taskkill /PID <会话PID> /T /F`，会话 PID 见界面）。
- 期望：1~3 秒内界面显示「启动失败」与线索文案，**此时合并按钮已回到「启动 DSH」（子进程已退出，点它就是重新启动）**；点「重启 DSH」后恢复「运行中」，链接就绪。

## 8. 单实例

- 操作：壳已打开时再次启动 DSHarbor（分别测：窗口在时 / 轻量态关窗后）。
- 期望：不出现第二个壳进程；窗口在时聚焦已有窗口；轻量态时自动重建窗口。

## 9. 配置持久化与端口覆盖

- 操作：改「启动方式/附加参数/端口」等项目 → 关闭壳 → 重开。
- 期望：刚才的配置原样恢复（`%APPDATA%\DSHarbor\config.json`）；端口填自定义值后启动，DSH 实际监听在该端口（界面与 `netstat` 一致）；填非法值（如 70000）点启动：明确报错、不启动、配置不落盘。

## 10. 桥接插件安装 / 卸载 / 回滚

- 操作：停掉 DSH → 「桥接插件」卡片点「安装桥接插件」（点按钮后「操作输出」自动展开并显示 pnpm/命令输出）；再测「卸载」；「恢复最近备份」；最后点「打开备份目录」。
- 期望：安装/卸载退出码 0 且提示「已登记/已摘除 dsh.profile.bundles」；安装后启动 DSH 登录徽章显示「桥接就绪」，卸载后降级为「日志兜底就绪」；恢复备份后 profile 文件与安装前逐字节一致（哈希清单在备份目录 manifest.txt）；**连做 6 次以上安装/卸载后，`%APPDATA%\DSHarbor\backups` 里只留最近 5 个 `backup-*` 目录，且被删掉的旧备份名写在「操作输出」的「旧备份清理」一行里**；**点「打开备份目录」用资源管理器打开 `%APPDATA%\DSHarbor\backups`（目录不存在时先建出来），卡片内提示「已在资源管理器中打开备份目录：<路径>」**；**卡片内四个按钮（安装桥接插件 / 卸载 / 恢复最近备份 / 打开备份目录）左对齐，与卡片内说明文字、表格同一左边缘**。

## 11. 卸载与数据保留

- 操作：Windows 设置 → 应用 → DSHarbor → 卸载（静默：安装目录下的 `uninstall.exe /S`；默认当前用户目录，若安装时改过路径以实际安装目录为准）。
- 期望：仅删除安装目录；`%USERPROFILE%\.dsh`（DSH 数据）与 `%APPDATA%\DSHarbor`（壳配置、DSH 版本号记录与桥接备份）完整保留。

## 排查

- **端口被占用（EADDRINUSE）**：profile 里 webserver 端口被别的程序占用（注意 WSL 镜像网络下 Windows/WSL 共用 localhost 端口，刚停过 DSH 时等 1~2 分钟 TIME_WAIT 消散）。改「端口」字段用自定义端口，或释放占用。
- **桥接未启用**：DSH 启动时没带 nonce（例如你自己在终端跑 `dsh web`），属预期降级（登录徽章显示「日志兜底就绪」）。
- **WSL 插件安装报 pnpm 错误**：确认壳运行时已注入清洗后的 PATH（4.0 起内置）；发行版内 pnpm 版本冲突时 `npx @deepseek-ai/dsh plugin --profile web …` 手动复核。
- **「安装桥接插件」报 `ERR_PNPM_PACKAGE_MANAGER_ADD_RESOLVE_LATEST`（v0.1.0 实机缺陷，已修）**：安装目录含空格（默认 `D:\Program Files\DSHarbor`）时，pnpm 会把 `file:` 规格在空格处截断后当包名去 registry 查。现在壳会先把插件包暂存到无空格目录（`%APPDATA%\DSHarbor\cache`，WSL 侧为 `/tmp/dsharbor-bridge`）再安装；若仍报错，检查暂存目录与 `TEMP` 是否都含空格。
- **看不到托盘图标**：Win11 默认折叠，拖到任务栏常显或点「隐藏的图标」。
