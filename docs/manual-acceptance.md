# Windows 手动验收手册（发布前完整流程）

每次发布前在 Windows 真机上按本手册复核。每步给出「操作」与「期望结果」；不满足时看文末「排查」。

> 开发机参考：自动化脚本与截图存放于 `C:\Users\<你>\AppData\Local\Temp\dsharbor-test`（`launch-app.ps1`、`capture-window2.ps1`、`kill-app.ps1` 等）。正式验收只需按本手册手动操作。

## 0. 构建与产物（WSL2 侧）

- 操作：`pnpm exec tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc`
- 期望：退出码 0；产物 `target/x86_64-pc-windows-msvc/release/bundle/nsis/DSHarbor_<版本>_x64-setup.exe`（2 MiB 量级；打包会连带前端构建与桥接插件 tgz）。

## 1. 安装

- 操作：双击安装包，按中文向导完成（静默安装等价命令：`DSHarbor_<版本>_x64-setup.exe /S`）。
- 期望：装到 `%LOCALAPPDATA%\DSHarbor`（当前用户，无需管理员）；注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\DSHarbor` 中 名称 DSHarbor、版本正确、发布者 BoxMiao007。

## 2. 启动与首次配置

- 操作：从开始菜单打开 DSHarbor（或运行 `%LOCALAPPDATA%\DSHarbor\dsharbor.exe`）。
- 期望：主窗口出现；「启动方式」默认「官方 npx 命令」；端口提示显示当前生效值（如「3080（来自 DSH 配置的 webserver 块，host …）」）；「桥接插件」卡片显示目标环境（Windows）与安装状态；「最近输出 / 操作输出」为折叠块——点击标题行展开、再点收起（空态显示「（暂无输出）/（暂无操作）」）。

## 3. 启动 DSH 并取登录链接

- 操作：点「启动 DSH」（首次会自动下载 npx 包，稍慢）。
- 期望：状态徽章变「运行中」，出现 PID 与端口；**点「启动 DSH」（或「停止」/「重新启动 DSH」）后同一卡片的「最近输出」自动展开**；「登录链接：桥接就绪」（未安装桥接插件时显示「日志兜底就绪」，同样可用）；**不会弹出系统浏览器**（壳自动追加 `--no-open`；界面用「当前程序打开」在壳窗口查看，或点「浏览器打开」显式交给系统浏览器）。失败时显示含退出代码与最近输出的提示，并给出诊断日志路径线索（`~/.dsh/logs/startup-*.log`）。

## 4. 两种打开方式与窗口独立性

- 操作：点「当前程序打开」；再点「浏览器打开」；然后先关 DSH 窗口（观察主窗口是否还在），再关主窗口（观察 DSH 窗口是否还在）。
- 期望：「当前程序打开」弹出的 DSH 窗口**已是登录态**（不需要手工拼接 token 链接），标题为 DeepSeek Harness；DSH 窗口尺寸随主显示器自适应（高度不越出屏幕下边界）；「浏览器打开」在系统默认浏览器打开同一界面；**两个窗口相互独立**——关 DSH 窗口后主窗口仍在；关主窗口后 DSH 窗口仍在（DSH 后端与托盘常驻），托盘「打开启动界面」可随时找回主窗口。

## 5. 轻量模式循环（3~5 轮）

- 操作：右键托盘确认菜单六档齐全（**浏览器打开 / 当前程序打开 / 打开启动界面 / 重启 DSH / 停止 DSH / 完全退出**）→ 关闭主窗口 → 任务管理器观察内存 → 单击托盘图标（默认打开启动界面；Win11 图标可能收在「隐藏的图标」小箭头里）。
- 期望：关窗后壳进程与 DSH 后端仍存活，界面内存明显下降（参考量级：两窗全开约 1037 MB → 关窗约 474 MB）；单击托盘后窗口原地重建，仍为「运行中」且登录链接就绪；重复多轮无白屏。在界面把「托盘单击打开」改为「当前程序打开的窗口」后，单击托盘应直接打开 DSH 窗口（未就绪时回退启动界面）。

## 6. 重启与完全退出

- 操作：托盘「重启 DSH」；再托盘「停止 DSH」；然后重新启动 DSH，最后托盘「完全退出」。
- 期望：重启后 DSH 的 PID 更换、登录链接重新就绪、窗口内容可用；「停止 DSH」后状态回「已停止」、PID/端口清空、`netstat` 无 3080 LISTENING，但**壳与窗口仍在**；完全退出后壳与 DSH 进程全部消失，`netstat -ano | findstr "3080"` 无 LISTENING 残留。

## 7. 意外退出恢复

- 操作：启动 DSH 后，在任务管理器结束其 node 进程（或 `taskkill /PID <会话PID> /T /F`，会话 PID 见界面）。
- 期望：1~3 秒内界面显示「启动失败」与线索文案；点「重新启动 DSH」后恢复「运行中」，链接就绪。

## 8. 单实例

- 操作：壳已打开时再次启动 DSHarbor（分别测：窗口在时 / 轻量态关窗后）。
- 期望：不出现第二个壳进程；窗口在时聚焦已有窗口；轻量态时自动重建窗口。

## 9. 配置持久化与端口覆盖

- 操作：改「启动方式/附加参数/端口」等项目 → 关闭壳 → 重开。
- 期望：刚才的配置原样恢复（`%APPDATA%\DSHarbor\config.json`）；端口填自定义值后启动，DSH 实际监听在该端口（界面与 `netstat` 一致）；填非法值（如 70000）点启动：明确报错、不启动、配置不落盘。

## 10. 桥接插件安装 / 卸载 / 回滚

- 操作：停掉 DSH → 「桥接插件」卡片点「安装桥接插件」（点按钮后「操作输出」自动展开并显示 pnpm/命令输出）；再测「卸载」；「恢复最近备份」。
- 期望：安装/卸载退出码 0 且提示「已登记/已摘除 dsh.profile.bundles」；安装后启动 DSH 为「桥接就绪」，卸载后降级为「日志兜底就绪」；恢复备份后 profile 文件与安装前逐字节一致（哈希清单在备份目录 manifest.txt）。

## 11. 卸载与数据保留

- 操作：Windows 设置 → 应用 → DSHarbor → 卸载（静默：`%LOCALAPPDATA%\DSHarbor\uninstall.exe /S`）。
- 期望：仅删除安装目录；`%USERPROFILE%\.dsh`（DSH 数据）与 `%APPDATA%\DSHarbor`（壳配置与桥接备份）完整保留。

## 排查

- **端口被占用（EADDRINUSE）**：profile 里 webserver 端口被别的程序占用（注意 WSL 镜像网络下 Windows/WSL 共用 localhost 端口，刚停过 DSH 时等 1~2 分钟 TIME_WAIT 消散）。改「端口」字段用自定义端口，或释放占用。
- **桥接未启用（日志兜底就绪）**：DSH 启动时没带 nonce（例如你自己在终端跑 `dsh web`），属预期降级。
- **WSL 插件安装报 pnpm 错误**：确认壳运行时已注入清洗后的 PATH（4.0 起内置）；发行版内 pnpm 版本冲突时 `npx @deepseek-ai/dsh plugin --profile web …` 手动复核。
- **看不到托盘图标**：Win11 默认折叠，拖到任务栏常显或点「隐藏的图标」。
