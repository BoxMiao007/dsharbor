# DSHarbor 界面评审报告（2026-10-21）

按 `/web-design-guidelines`（Web Interface Guidelines 合规）与 `/frontend-design`（视觉设计）两条线评审当前 Web 界面。

**范围**：`src/styles/*.css` 全部样式分片、`src/ui/build-html.ts`（整页静态骨架）、`src/main.ts`（交互装配）中与界面相关的部分。
**方式**：静态读代码 + 在假数据预览台上用 Edge 实测（对比度自算 sRGB 相对亮度、焦点环读 computed style、截图见 `.tmp-shots/`）。
**性质**：只读评审，未改动任何源码。本文所有 `file:line` 均按当前工作区代码核对。

## 结论速览

界面成熟度不低：冷灰蓝双主题克制、层次靠明度差而非描边、动效收口到 `--btn-*` 变量、自绘下拉键盘可达、`color-scheme`/`tabular-nums` 等细节到位。但用两个 skill 的标尺卡下来，有 **2 个用户可直接感知的硬伤**，其余是系统性的可访问性欠账与小瑕疵。

| 级别 | 问题 | 一句话 |
| --- | --- | --- |
| **P0** | 强调底上的白字对比不足 | 深色主按钮「启动 DSH」仅 **2.67:1**，最显眼的按钮反而最难读 |
| **P0** | 全站无统一可见焦点环 | 默认焦点环近黑 `rgb(16,16,16)`，深色底上几乎不可见 |
| P1 | 次要文字 / 浅色状态色低于 AA | `--fg-mute` 深 3.88、浅 3.11；浅色 `ok` 3.44、`warn` 3.25 |
| P1 | 状态与错误区无 `aria-live` | 异步刷新的徽章 / 错误读屏听不到 |
| P1 | 浮窗无焦点管理 | 打开不进入、不圈定、关闭不还原 |
| P2 | 四个输入框无 label | 仅靠 placeholder |
| P2 | reduced-motion 漏掉无限转圈 | 重启 / 方形按钮的持续旋转不受控 |
| P3 | 标题层级 / 语义 / 死规则 | 零 `<h1>`、重复 CSS 定义 |

## A. Web Interface Guidelines 合规

### A1. 焦点状态（全局，最优先）

- `src/styles/60-controls.css:14` `button { … }` 无 `:focus-visible` 规则。实测 Tab 遍历顶栏窗口钮、左栏导航、图标钮、会话主按钮，computed `outline` 均为 `auto 1px rgb(16, 16, 16)` —— 近黑色，落在 `#0b0f14` 深底上基本看不见。`#btn-open-more` 同样无可见环。
- 唯一例外（可作为正面范例）：`src/styles/90-modals.css:265` `.switch:focus-visible { outline: 2px solid var(--accent); … }`，对比清晰。
- `src/styles/50-info.css:75-77` `.info-dot:focus-visible { outline: none }` 移除焦点环，仅靠 `::after` 气泡块出现顶替；桌面上鼠标也可触达，但键盘用户失去位置反馈，记为弱替代。
- `src/styles/60-controls.css` 输入框聚焦用 `border-color` 变色替代 `outline`（1px 变色），勉强可接受，但与按钮的焦点语言不统一。

**建议**：在全站交互元素上补一条统一规则（示例，非既定方案）：`button:focus-visible, a:focus-visible, input:focus-visible, .picker-btn:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`，并保留 `.switch` 现有规则；`.info-dot` 补回可见环而非置 `none`。

### A2. 无障碍 / 语义

- `src/ui/build-html.ts:80` 登录徽章 `#login-badge`、`:81-82` 版本徽章 `#version-badge`、`:83` PID/监听等状态由轮询异步写入，容器无 `aria-live`，读屏用户听不到状态变化。建议状态容器加 `aria-live="polite"`。
- `src/ui/build-html.ts:110` `#status-error` 与 `:111` `#login-note` 为动态错误/提示 `<p>`，缺 `role="alert"` 或 `aria-live`；同类 `.error`（`60-controls.css:393`）仅做视觉。
- `src/ui/build-html.ts:429, 436, 446` 三个浮窗 `role="dialog" aria-modal="true"` 与 `aria-labelledby` 都有，但 `src/main.ts:1846-1855 setModal()` 只切 `hidden` 类：打开时焦点不进入浮窗、不 trap、关闭不还原；浮窗打开时背景仍可 Tab 到。建议加 inert / 焦点圈定与 init、return focus。
- `src/ui/build-html.ts` 整页零 `<h1>`–`<h6>`：标题都是 `.col-title`、`.titlebar-name` 一类 `<span>`（见 `src/styles/40-content.css` 的 `.col-title`）。桌面壳可放宽，但读屏按标题跳转会很差；另无 skip link。
- `index.html` 缺 `<meta name="theme-color">`（与页面底色同步）。桌面 WebView 影响小，属锦上添花。

### A3. 表单

- 四个文本输入框**无 `<label>` 也无 `aria-label`**，仅靠 placeholder：
  - `src/ui/build-html.ts:181` `#proxy-address`（placeholder「例如 http://127.0.0.1:7890」）
  - `:303` `#binary-path`（「例如 D:\tools\dsh.cmd」）
  - `:320` `#custom-command`（「例如 npx @deepseek-ai/dsh@next web」）
  - `:453` `#profile-manage-name`（「例如 lab」）
  建议给每个补 `aria-label`（或可见 label）。对照：同行的「浏览程序路径」按钮 `:304` 有 `aria-label`，说明标准已在用，只是输入框漏了。
- placeholder 以示例值充当标签，可读性弱；如需保留，建议改为「标签 + 示例」并存，示例放 helper。
- 正面：`spellcheck="false"`、`autocomplete="off"` 在 `:181`、`:453` 等已正确加上。

### A4. 动效

- `src/styles/60-controls.css:377` `@media (prefers-reduced-motion: reduce)` 只覆盖了逐字切换等有限项；**未覆盖** 无限循环类：`#btn-restart.is-restarting svg`（`:227` 持续旋转）、`.square-btn.is-spinning svg`（`:488`）。功能反馈可保留，但建议这些无限动画在 reduce 下降频或静止（或在 reduce 下改为静态指示）。
- 正面：未发现 `transition: all`；动画基本走 `transform` / `opacity`。

### A5. 深色模式 / 排版

- 主题切换只改 `<html data-mode>`（见 `src/ui/theme.ts` 的 `applyMode`），不重载页面，做得对。
- 正面：加载态用真省略号、`ico-count` 与备份时间用 `tabular-nums`。PID / 端口的 `status-meta` 数字未用 tabular，属可选项。

### A6. 代码卫生（顺带，非用户可见）

- `src/styles/30-toolbar.css:91` 与 `src/styles/50-info.css:113` 各定义一份 `.status-meta`；`.status-meta b` 的 `font-weight` 两处冲突（600 vs 500），后加载者胜，前者成为死规则。
- `src/styles/30-toolbar.css:118` 的 `.login-note`（`margin: 0 14px 8px`）被 `src/styles/60-controls.css:5` 的 `.login-note`（`margin: 0`）整段覆盖成死规则。

## B. 视觉设计评审（frontend-design 视角）

### B1. 做对的（保持）

- **配色有主见且克制**：深色冷灰蓝 `--bg:#0b0f14` + 单一强调蓝 `--accent:#4ea1ff`，浅色同族反相；层次靠 `card → cell` 明度差，不在每张卡上叠阴影。避开了「奶油底 + 陶土红 / 荧光绿」这类模板脸。
- **一个记忆点**：主按钮逐字切换 + 轻抖、停止/重启圆钮的图标反馈，个性集中花在一处，周围保持安静，符合「boldness 花在一个地方」。
- **系统字体是合理选择**：Windows 桌面壳用 Segoe UI / Microsoft YaHei 的原生感是对的。
- **间距 / 圆角 / 动效变量收口**，可维护性好。

### B2. 可改进

1. **强调色对比（最影响观感）**：白字压在 `--accent` 上，深色仅 2.67:1（hover 2.27）。要么把 accent 调深、要么主按钮改用深色文字。这是「最响的按钮读不清」。
2. **次要文字偏灰偏小**：`--fg-mute`（`00-tokens.css:53` 深 `#6d7a8a` / `:83` 浅 `#8494a5`）在卡片上 3.88:1 / 3.11:1，却大量用于 11.5–12px 的 `.hint`（`60-controls.css:717`）、`.env-card-meta`（`80-env-cards.css:67`），长段说明读起来发虚。
3. **浅色态状态色不达标**：`--ok:#1e9e5f`（3.44）、`--warn:#b8860b`（3.25）在白底做小字/徽章文字低于 AA；深色态反而都合格。
4. **文案密度**：插件卡、命令行集成、缓存卡是整段长 hint 平铺。可把说明收进 `ⓘ` 气泡或折叠，卡片本身只留一行结论（`ⓘ` 机制 `50-info.css` 里已有，直接复用即可）。
5. **视觉层级**：`.col-title`（15px / 700）与 `.mode b`（14px）与正文差距不够，六张卡标题可再拉开一点，或给卡片统一小节节奏。

### C2. 按钮
