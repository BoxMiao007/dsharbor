界面候选（10 套，三批）

九套都是可点的静态稿，假数据完全一样（运行中 · 桥接就绪 · npx 启动），横向比的只有布局、配色和操作方式。点开任意一套，窗口大小按卡片上标的调一下再看，最贴近正式窗口时的样子。

基线对照：当前线上界面（正式界面 + 假数据）。打不开就先在仓库里跑一次 node scripts/mock-preview.mjs --no-serve。

第三批 · 换皮

结构、类名、文案全部照搬正式界面，只叠一层新皮肤
J

原界面 + 系统原生主题

布局一格没动，只换配色与控件形状
做法：正式界面的 src/style.css 照旧管排版，再叠一层 native-theme.css，把候选 I 的配色与控件形状逐条搬过来
排版 100% 现状：标题栏 / 卡片位置 / 字段顺序 / 字号
        ↓ 只换外观，数值全部抄自候选 I
窗口底 #202020 · 面板 #2b2b2b · 强调 #4cc2ff
单选变系统圆圈 · 下拉变 ComboBox（亮底线）
端口带上下箭头 · 日志去外框 · 徽章 26px 胶囊

外观一个数值没另调，布局一格没动，所以最容易反悔；代价是这套皮是深色系统设置风，跟现在的雾光蓝是两种气质。窗口按正式默认尺寸看。

也可以混着来

  • 比方说：H 的极简主界面 + F 的分段控件改设置 + I 的系统下拉框，选一个方案为主体，再从别处搬两三个控件过来。
  • 看的时候重点感受「改一个选项要几步」：F / G 是一步（点一下就完），H 是两步（唤起面板 + 选中），I 是三步（点下拉 + 看选项 + 再点一下）。
  • 哪一套的「DSH 有没有跑起来、链接能不能点」最容易被一眼看到——这是这个界面最主要的用途。

这九套都是静态稿，只用来比较布局、配色和操作方式；选定之后再按它把真实界面重做一遍（真实交互、真实数据都在正式实现里做）。
